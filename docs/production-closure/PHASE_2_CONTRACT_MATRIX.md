## Actual HTTP contracts to preserve

- Review request: `{operationId, requestHash, checkoutVersion}`. Response contains status, review version, commercial fingerprint, merchandise/modifier/delivery/promotion/grand totals, changes, quotes and legal evidence. Acknowledgement also requires review version, fingerprint, acknowledged total reference, terms/privacy versions and nonempty refund policy references.
- Reserve/prepare-payment routes allow `{checkoutVersion, operationId, requestHash}` but currently pass **operationId, not requestHash**, into their checkout service commands. Treat request-hash conflict enforcement as a proof question; do not infer it from allowed JSON keys. Reserve returns reservation reference/status; preparation returns canonical payment reference/amount/currency/customer action or replay.
- Store actions are `begin-review`, `accept`, `bridge-delivery`, `reject`, `confirm-availability`, `propose-substitution`, `start-preparation`, `update-preparation-time`, `mark-ready`, `generate-pickup-code`. The server hashes action and exact submitted body. Customer actions are `substitution-preference`, `decide-substitution`, `request-cancellation`. Driver handoff accepts only operation ID, pickup code and package count; driver identity comes from authentication.
- Refund creation schema is strict `{paymentPublicReference, amount, method, reasonCode, customerNote?, operationId}`; exact decimal amount string. Cancellation/completion uses `{operationId}`; finance decision may add `financeNote`. Customer path uses `RF-...` public reference; admin path uses opaque internal ID resolved to canonical public reference. Mutation body policy requires JSON content type and content length ≤4096.
- Paystack ingress returns RECEIVED acknowledgment without applying financial success synchronously. Background application performs a Verify transaction call before amount/currency/status matching and ledger effect. `clientOverride` exists in application composition; ordinary claimed processor/browser execution still needs a faithful, bounded offline seam.
