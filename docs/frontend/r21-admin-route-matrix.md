# R21 verified administration route matrix

Verified against the live `app/(admin)/admin` tree on 2026-07-29: 105 R21
routes. Every route now renders inside the server `AdministrationWorkspace`
protected-v2 boundary. The exact server guard, service/DTO, pagination/filter,
canonical action, optimistic version, maker-checker policy, audit event, and
production lock remain the authority.

## Matrix key

- All routes require the existing ADMIN/SUPER_ADMIN layout context plus their
  existing route permission. ADMIN is not a universal grant; SUPER_ADMIN is not
  a client-only bypass.
- “Existing authority” means the current route module/service/API is retained.
  R21 adds no backend logic, DTO, API, database, permission or state-machine.
- List routes use their existing server query/filter/page authority; dynamic
  routes retain dedicated server retrieval. Mobile strategy is labelled record
  lists or protected detail panels, not a compressed page-wide table.
- Locked/restricted/scaffold states remain truthful. A dash action is read-only,
  never an implied operation.
