# Phase 10 implementation map

This mandatory pre-implementation map records the payment placeholders and the contracts Phase 10 will evolve. It was written before the Phase 10 schema, services, routes, or UI were changed. The accepted migration chain ends at `20260717010000_phase9_wallet_ledger_system`; those migrations are immutable.

## Existing payment-model inventory

Repository-wide searches of `app`, `lib`, `prisma/seed.ts`, and `tests` found no runtime or seed writer for `Payment`, `PaymentAttempt`, `PaymentWebhookEvent`, or `PaymentRefund`. Payment coverage before this phase is limited to Phase 4 schema-presence/money-field tests and Phase 9 documentation that classifies these records as future placeholders.

## Transaction and external-call map

Provider calls are dependency-injected calls and are never made from a Prisma transaction callback. Serializable database retry is bounded to recognized serialization/deadlock conflicts.

| Operation | Database reads / locks | Database writes | External call | Error / rollback / recovery |
|---|---|---|---|---|
| Prepare payment | Before transaction resolve owned order + quote + existing success. In serializable transaction read preparation key and order payment state. | One `Payment(CREATED)` and one initial history row. | None. | Invalid ownership/status/money is non-retryable. Same key/hash replays; mismatch conflicts. Any create/history error rolls back both; unique race re-reads winner. |
| Reserve attempt | Serializable transaction reads key; parameterized `SELECT ... FOR UPDATE` locks payment; re-reads authoritative identity/status. | Increment `latestAttemptNumber`/version, create `RESERVED` attempt, set payment `PROVIDER_PENDING`, add history. | None. | Semantic/config/capability errors do not consume a key. Same key/hash replays. Any failure rolls back counter, attempt, status and history; recognized DB conflicts retry boundedly. |
| Call adapter | No open transaction. Registry/config/capabilities are resolved after reservation. | None while call is in flight. | Exactly one `createCheckoutSession` call per new reservation, bounded by `AbortController`; no blind retry. | Definite local/provider errors normalize to failure. Potentially transmitted timeout/network/malformed outcomes normalize UNKNOWN. Crash leaves durable merchant reference and unresolved attempt for later recovery. |
| Record provider response | Serializable transaction locks payment then attempt; validates unresolved/current versions and provider result. | Safe result snapshot/ref/redirect/times; attempt and payment transitions; history. | None. | Invalid redirect or malformed definitive response fails closed. Same concurrent finalization returns winner if equivalent; incompatible winner conflicts. Transaction failure leaves attempt unresolved with durable reservation for reconciliation. |
| Record definite failure | Same finalization locks/read order. | Attempt `FAILED`, normalized safe category/code/messages, payment `FAILED`, history. | None. | Raw exception/stack/credentials are discarded. Rollback leaves unresolved reservation. Later explicit command may reserve a new attempt. |
| Record unknown outcome | Same finalization locks/read order. | Attempt `UNKNOWN`, payment `PROCESSING`, safe category/evidence, history. | None. | UNKNOWN is never failure. Automatic new attempt is blocked unless later provider capability/status proof permits it. |
| Replay command | Read unique preparation/attempt command key and canonical hash. Completed attempt can be returned directly; unresolved attempt returns pending state. | None. | None after a final result; no duplicate call. | Changed hash produces typed conflict. Crash-before-call reservation may be resumed only by the documented same-key policy. |
| Create retry attempt | Lock payment in `FAILED` or `EXPIRED`; verify no UNKNOWN/current unresolved attempt. | Increment counter and create a distinct reserved attempt; payment returns to pending; history. | Per normal Stage B after commit. | Terminal success/cancel and unknown outcomes block retry. Amount/currency/order/payer remain immutable. |
| Expire pending attempt | Future/internal finalization path locks payment and attempt. | Attempt `EXPIRED`, payment `EXPIRED`, history. | None. | Only legal central transitions; no public mutation route in Phase 10. Rollback leaves prior state. |

Lock order is always Payment followed by PaymentAttempt. Merchant reference format is `kt:payment:<non-sequential-public-reference>:attempt:<positive-number>` and remains stable for the attempt.

## Route and UI map

Next.js 16 dynamic `params` and page `searchParams` are promises and are awaited. Routes export only `GET`, so unsupported writes retain framework 405 behavior.

| Route | Method / authorization | Request and response | UI contract and states | Stable locator |
|---|---|---|---|---|
| `/api/admin/payments` | GET; admin/SUPER_ADMIN + `payments.read`, explicit DENY wins for ADMIN | strict page/pageSize, public/order ref, payer, status, provider, date and safe amount filters; paginated safe summary DTO, money strings | consumed by `/admin/payments`; labelled GET filters, deterministic pagination, explicit empty/error/loading states | exact heading `Payments`; table accessible name `Payments`; labels `Payment status`, `Payment provider`, `Order reference` |
| `/api/admin/payments/[id]` | GET; same permission | awaited ID; safe payment summary, ordered attempts and history; no request hashes, credential data, or raw snapshots | consumed by `/admin/payments/[id]`; not-found is inaccessible; read-only summaries and empty attempt/history states | exact heading `Payment details`; tables `Payment attempts` and `Payment lifecycle history` |
| `/api/admin/payment-providers` | GET; admin/SUPER_ADMIN + `payment_providers.read`, explicit DENY wins | no request body/query; known/configured/active, capability booleans and safe config error category only | consumed by `/admin/payment-providers`; missing PayFast config is a readiness state, not a page error | exact heading `Payment Providers`; table `Payment providers` |
| `/admin/payments` | GET page; `payments.read` | awaited URL filters validated by the query schema; service DTO rendered server-side | filters, list, pagination, empty/error state; `loading.tsx` supplies navigation loading state | page heading `Payments` |

No payer status endpoint or customer checkout UI is added in Phase 10. No public payment mutation/session route is planned.

## Migration-state declaration

The single new migration will be `prisma/migrations/20260717020000_phase10_payment_provider_foundation/migration.sql`. It will fail closed if any legacy payment/attempt/refund row makes deterministic status/type evolution unsafe; it will not fabricate PayFast assignment, provider references, success, amount, or accounting evidence. No existing migration will be edited and the migration will not be executed during this implementation phase.
